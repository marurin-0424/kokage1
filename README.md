# こかげ

建物の影から、子連れの夏の外出を変える。

都知事杯オープンデータ・ハッカソン2026 応募作品（テーマ：気候変動）

公開ページ → **[index.html](./index.html)**

夏の午後、3〜5歳を連れてどこで遊ばせるか。天気予報は今日の暑さを、地図アプリは近い公園を教えてくれますが、**その公園まで歩く道のどこが日陰か**は、どちらも教えてくれません。こかげは、3D都市モデルから建物と高架の影を計算して、そこを埋めます。

対象は **池袋駅周辺 約2.5km × 1.1km**（歩行空間ネットワークデータの収録範囲）です。

## 3つのステップ

1. **何時に出るか** — 11〜16時の6枚。待つ価値がある時刻と、**悪くなる時刻**の両方を出します。**暑さ指数31以上の時刻には、屋外の行き先を出しません**（幼児・学童には一つ上の温度基準域を当てます）
2. **どこへ行くか** — 候補3件を、公園の影の形とあわせて。**選ぶのは利用者です**
3. **どの道で行くか** — **ここだけは、こかげが決めます。**最短の道より 1.8% だけ遠回りすると、往復で日なたにいる時間が 31% 減ります（14時・n=400 の中央値。0.5分以上減るのは84%）

②で決めず③で決めるのは、精度の裏づけが違うからです。**道路の影は現地確認3回とも概ね一致しましたが、公園の影は 9〜32ポイント少なく見ています**（樹木が入っていないため）。

## 計算スクリプト

`src/` に置いてあります。Python 側の依存は **shapely / pyproj / pvlib / networkx の4つだけ**です（手元で再現できることを設計目標にしたため）。座標系は EPSG:6677。CityGML は変換ツールを挟まず `zipfile` と正規表現で直接パースしています。

| ファイル | 役割 |
|---|---|
| `src/shadow.py` | 太陽位置と建物の影 |
| `src/bridge.py` | 高架デッキの影と、デッキ下 |
| `src/route.py` | 熱ストレスを重みにした経路探索（Python 側） |
| `src/hydration.py` | 発汗量の推定 |
| `src/screen6.py` | 6時刻ぶんの答えを計算（`out/screen6.json`） |
| `src/park_svg.py` | 公園の影の形（`out/park_svgs.json`） |
| `src/hour_pick.py` | 時刻ごとの歩道の日陰率と、暑さ指数の実測集計 |
| `src/degrade.py` | 退化テスト（順位が距離順と一致していないかを測る） |
| `src/build_v1.py` | v0〜v1b の画面HTMLの生成 |

### v1c（出発地を任意地点にするため）で足したもの

| ファイル | 役割 |
|---|---|
| `src/kokage-engine.js` | **ブラウザ側の経路探索エンジン。**画面HTMLに埋め込んで使います |
| `src/graph_export.py` | エンジンが読むグラフを書き出す（`kokage_graph.json`） |
| `src/map_export.py` | 地図の素材を書き出す（リンク・公園・建物・時刻ごとの影） |
| `src/labels_export.py` | 地図の目印を書き出す（`map_labels.json`） |
| `src/facility_hours.py` | 屋内施設の開館時間を書き出す（`facility_hours.json`） |
| `src/parity_test.mjs` | **JS エンジンと Python の答えを突き合わせます。**判定するのは**滞在mLの一致**（18/18・差0）で、ここがずれたら回帰です。**移動mLの差（+12〜30mL）と順位の差は意図的**で、2026-08-22 に終点のスナップを「公園の点」から「ポリゴンの縁」に変えた分です |
| `src/detour_measure.mjs` | **迂回係数 1.3 を、この街の歩行空間ネットワーク上で実測して検証します。**実経路長÷直線距離の中央値 **1.291**（n=89,427）と、1位・2位・3位が入れ替わる境界を出します |
| `src/smoke_v1c.mjs` | **煙テスト13項目**（Playwright。実際に押して確かめる形で回帰を検出します） |

`out/` は計算結果のJSONです。画面はここから生成されます。

```bash
cd src
PYTHONPATH=. python3 build_v1.py        # v0〜v1b の画面を生成
node parity_test.mjs                    # JS エンジンと Python の答えを並べて見る
```

煙テストは HTTP で開く必要があります（`fetch` を使うため `file://` では動きません）。

```bash
python3 -m http.server 8099             # publish/ の中で
node src/smoke_v1c.mjs http://127.0.0.1:8099/kokage-v1c-mobile.html
```

## 前提と限界（自分から書いておきます）

- **日影は 2026年8月12日の太陽位置**による計算値で、**晴天時の値**です。曇りの日の補正は入っていません
- **公園の日陰に樹木は含まれていません**（建物と高架の影のみ）。現地確認では、実際より **9〜32ポイント少なく**見ていました。だから公園については**割合の数字を出さず、形だけを見せています**
- **暑さ指数の既定は、環境省（練馬と東京の高い方）の実況＋予測**です。過ぎた時刻は実況、これからの時刻は3時間刻みの予測を内挿しています。画面から自分で指定することもできます（21〜35℃）
- **どの観測点を採るかで、答えは ±28〜41% 動きます。**12〜15時で都内3地点の幅が平均2.18℃あるためです。安全側に倒して「高い方」を採っています。**豊島区内に観測地点はありません**
- 建物は LOD2 実形状585棟＋LOD1。**LOD1 の箱では上階がすぼむ形（斜線制限）を表現できず**、公園の日陰率が過大に出ます
- 歩行速度 53.1 m/分 は、3〜5歳を連れた実測です（**同一の親子1組で3区間**・170m／650m／600m・51.6〜54.5 m/分を距離で加重）
- **直線距離→実距離の迂回係数は 1.3** です（`[R-19]` 腰塚・小林 1983「In Urban areas, R = 1.3u」）。★ **この街の歩行空間ネットワーク上でも実測しました：中央値 1.291**（n=89,427・四分位 1.174〜1.440・`src/detour_measure.mjs`）。**1位はこの係数を 1.05〜1.50 に振っても変わりません**が、**2〜3位には 1.26／1.28／1.38 に入れ替わりの境界があり、既定 1.3 は境界から 0.02 しか離れていません**
- 保護者へのヒアリングは**1名**です
- 収録範囲の外では答えを出せません。**歩行空間ネットワークデータが整備されているのは都内17地区だけ**で、そのうち2018〜2021年の整備で止まっているのが16地区です（更新されたのは赤羽駅周辺のみ）
